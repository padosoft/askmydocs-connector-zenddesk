# Development

## Setup

```bash
git clone https://github.com/padosoft/askmydocs-connector-zenddesk.git
cd askmydocs-connector-zenddesk
composer install
```

`composer.json` declares a VCS repository for `padosoft/askmydocs-connector-base` (it is not on Packagist yet). To develop against a local checkout of the base package without touching the committed manifest, copy `composer.json` to an ignored `composer.local.json` and replace its `repositories` entry with a `path` repository:

```json
"repositories": [
  { "type": "path", "url": "../askmydocs-connector-base",
    "options": { "symlink": true, "versions": { "padosoft/askmydocs-connector-base": "1.6.0" } } }
]
```

then run `COMPOSER=composer.local.json composer install`. Both `composer.local.*` and `composer.lock` are git-ignored: lock files are generated by the release manager, not committed with feature work.

> In sandboxes where `api.github.com` is not reachable, Composer's default zip downloads fail. `composer install --prefer-source` clones from `github.com` instead, and `phpstan/phpstan` can be run from the `phpstan.phar` shipped in a clone of <https://github.com/phpstan/phpstan>.

## Commands

| Command | What it does |
|---|---|
| `composer test` | PHPUnit 11/12 with Orchestra Testbench, in-memory SQLite, simulated HTTP |
| `composer analyse` | PHPStan level 6 over `src/` |
| `composer format` / `vendor/bin/pint --test` | Laravel preset code style |

CI (`.github/workflows/tests.yml`) runs all three on PHP 8.3 and 8.4 against Laravel 12 and 13.

## Test layout

| File | Covers |
|---|---|
| `tests/Feature/ConnectorTest.php` | Registration, capabilities, credential form, verification, health, sync entry points, disconnect, provenance, source ACL, remote ids |
| `tests/Feature/HttpClientTest.php` | Subdomain and URL policy, both auth modes, retries, `429`, sanitisation, body caps, download redirects |
| `tests/Feature/SyncTest.php` | Full scans, idempotency, switches, deletions on evidence, attachments, rate limit, resume, locks, cancellation, tenant isolation |
| `tests/Feature/ToolsTest.php` | Catalog scoping, argument validation, each tool family, pagination, truncation, errors |
| `tests/Feature/AgentUsageProfileTest.php` | The published profile matches the live catalog |
| `tests/Feature/FakesZendesk.php` | A small in-memory Zendesk used by the scan tests |
| `tests/FakeIngestion.php` | A recording `ConnectorIngestionContract` |

Conventions: a fake response must be created **per request** (a streamed body can be read once); tests that depend on time compare against `now()` with a tolerance, never a literal date.

## Adding a content type

1. Add the renderer to `Support\Markdown` (pure function).
2. Add an importer method to `DocumentImporter` that ends in `write()` and chooses an ACL from `SourceAccessPolicy`.
3. Add a phase to `SyncManager::PHASES`, a `…Step()` method, a case in `step()` and an entry in `enabled()`.
4. Add the kind to `Support\RemoteId::KINDS` and handle it in `readAcl()`.
5. Add a settings field to `connectionSettingsSchema()` and document it in the README table.
6. Add tests for: first import, no re-delivery when unchanged, deletion evidence, switch off.

## Adding a live tool

1. Add a definition to `ZendeskTools::definitions()` (closed schema, `additionalProperties: false`).
2. Map it in `request()` and, if the response key differs, in the record type logic.
3. Whitelist its output fields in the field constants — never forward the raw row.
4. Add it to `capability()` and to `resources/agent-usage.json` (`tools`, routing, workflow). `AgentUsageProfileTest` fails if they drift.
5. Update [live-tools.md](live-tools.md).

## Release checklist

- [ ] `composer test`, `composer analyse`, `vendor/bin/pint --test` green
- [ ] README tables and docs match `config/connector-zendesk.php` and the settings schema (docs must match code)
- [ ] CHANGELOG entry
- [ ] Tag `vX.Y.Z` on `main`; the host then requires `^X.Y`
- [ ] If a "not re-read" API item in [zendesk-api.md](zendesk-api.md) was validated on a real account, update its status
